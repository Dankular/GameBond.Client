# Per-flow exit balancing

Set `exit_flow_balance` to `true` with at least one `peer_backups` entry to distribute new IP flows across the primary and healthy warm exits. Each flow stays pinned to one exit so its return path reaches the same server-side NAT and conntrack state. The client weights new assignments by configured egress capacity, measured RTT, and the optional hop-count hint, then chooses the least-loaded exit using its offered rate and active session count.

The client keeps each exit's independent GameBond sender, receiver, pacing queue, and authenticated standby session. It now accepts application data and replies on ready standby sessions. Existing flows remain pinned while an exit recovers and move only after its health circuit opens or failover replaces it. Because exits have different public IPs and local NAT state, a reassignment can reset an established TCP connection; new flows continue on healthy exits. Planned primary changes are disabled in this mode so healthy sessions remain pinned.

Layer 2 Ethernet frames and packets without a parseable IP flow stay on the active exit. The flow table is bounded at 262,144 entries. TCP mappings expire after two idle hours, UDP after five minutes, and other IP flows after thirty seconds; the TCP close grace starts after both FIN directions or an RST. Status reports each exit's current flow count, packets and bytes by direction, and reassignment/untracked counts.

New assignments use a weighted least-load score: measured bidirectional flow rate plus a small active-session floor, divided by configured capacity adjusted for measured RTT and hop count. Replies refresh the same bidirectional flow entry, so downloads stay pinned even when the client sends little. Status reports current flow sessions, packets/bytes by direction, offered Mbps, reassignments, and untracked flows per exit.
